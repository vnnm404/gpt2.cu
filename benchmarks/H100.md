# H100 training throughput branch

This branch starts from RTX 3080 commit `d1611e6`. H100 results have not yet
been measured. Existing RTX 3080 JSON files remain historical measurements.

Optimize sustained training throughput at large **physical per-GPU batches**.
Gradient accumulation alone does not enlarge the matrices seen by the kernels.
Start with batch sizes 32, 64, and 128 at sequence length 128, increasing until
memory capacity or throughput saturation limits the sweep. These are candidate
workloads, not claims that every shape fits. Report tokens/second, step time,
and total elapsed training time at each shape; compare identical shapes,
precision, initialization, inputs, and optimizer settings.

Both benchmark entry points now default to batch 32 and sequence 128, and accept
`--batch` and `--sequence`. The existing attention implementation requires
sequence lengths from 1 to 256. Longer contexts require implementation work.

```sh
mkdir -p benchmarks/results
for batch in 32 64 128; do
  uv run python benchmarks/compare.py --batch "$batch" --sequence 128 \
    --steps 5 --iterations 50 --output "benchmarks/results/h100-b${batch}-t128.json" || break
done
uv run --with tiktoken python benchmarks/train.py --text /tmp/shakespeare.txt \
  --batch 32 --sequence 128 --mode pytorch --steps 200 --output /tmp/h100-pytorch.json
uv run --with tiktoken python benchmarks/train.py --text /tmp/shakespeare.txt \
  --batch 32 --sequence 128 --mode persistent --steps 200 --output /tmp/h100-persistent.json
```

For the historical RTX 3080 workload, pass `--batch 4 --sequence 64` explicitly.
The Python build detects the active GPU compute capability and caches a separate
shared library for that architecture. With CMake, set
`-DCMAKE_CUDA_ARCHITECTURES=90` explicitly for H100. This compiles the existing
FP32 SIMT implementation for H100; it does not yet implement Hopper tensor-core
kernels. Cooperative worker residency remains queried from the compiled kernel
and actual device, with no hardcoded SM count.

Next optimization work should establish the large-batch baseline, profile GEMMs
and activation memory use, and then optimize standalone kernels before changing
the persistent schedule. Keep FP32 results separate from any future BF16 or
TF32 results; precision changes require a matched PyTorch baseline and renewed
correctness checks. Repeat sanitizer and residency checks on H100 before making
performance claims.
